«Сессии» раз в минуту-две спрашивают у панели, кто сейчас онлайн на каждой ноде. Сама прослойка делает это по очереди: поставила задание первой ноде, второй, третьей — и ждёт ответы. При десятке нод опрос растягивается, а часть нод не успевает ответить.

Go-сервис опрашивает все ноды сразу и отдаёт прослойке готовый результат. Ещё он собирает список пользователей панели — страницы параллельно, а не одну за другой (см. [«Список пользователей»](#go-users)). Всё остальное — запись сессий, гео, аномалии, «Сейчас онлайн», сброс соединений в карточке, вкладка «Пользователи» — по-прежнему делает прослойка.

<Callout>
Go-сервис не обязателен. Без него всё работает как раньше. Если он перестанет отвечать, прослойка сама вернётся к своему опросу и сама соберёт список — ничего не прервётся.
</Callout>

## Что нужно [#go-need]

* Для опроса нод — включён сбор сессий: «Пользователи» → блок «Сессии» → «Собирать историю сессий». Список пользователей Go собирает и без этого.
* Docker на сервере прослойки. Для установки файлами Go-сервис тоже ставится контейнером — рядом с сайтом.

## Установка [#go-install]

<Steps>
<Step>

### Скопируйте секрет [#go-secret]

«О системе» → блок «Go-сервис» → «Секрет» → кнопка копирования. Без секрета Go-сервис не примет запросы — так никто, кроме прослойки, не сможет гонять через него запросы к панели.

</Step>
<Step>

### Добавьте сервис [#go-add]

<Callout type="warn">
Сейчас Go-сервис есть только в тестовой ветке: образ Go — с тегом `dev`, и прослойка тоже должна быть на `dev`. В Docker — тег `dev` у образа прослойки (или `SUBMW_IMAGE_TAG=dev`), при установке файлами — `git fetch && git reset --hard origin/dev` в папке сайта. Тег `v1` у образа Go появится с ближайшим релизом прослойки.
</Callout>

<Tabs groupId="go" persist items={['Рядом с панелью', 'Отдельный сервер', 'Установка файлами']}>
<Tab value="Рядом с панелью">

Допишите в `docker-compose.yml` прослойки в раздел `services:`:

```yaml title="docker-compose.yml"
  submw-go:
    image: ghcr.io/mrvibecodic/remnawave-subscription-middleware-go:dev
    container_name: submw-go
    hostname: submw-go
    restart: always
    networks:
      - remnawave-network
    environment:
      - SUBMW_GO_SECRET=секрет_из_админки
    logging:
      driver: json-file
      options:
        max-size: 10m
        max-file: '3'
```

Сеть та же, что у прослойки: Go ходит в панель по тому же адресу, что и она (`http://remnawave:3000`).

</Tab>
<Tab value="Отдельный сервер">

Для любого compose отдельного сервера — со своим реверс-прокси, с Caddy или с nginx из файла. Допишите в `docker-compose.yml` прослойки в раздел `services:`:

```yaml title="docker-compose.yml"
  submw-go:
    image: ghcr.io/mrvibecodic/remnawave-subscription-middleware-go:dev
    container_name: submw-go
    hostname: submw-go
    restart: always
    networks:
      - submw-net
    environment:
      - SUBMW_GO_SECRET=секрет_из_админки
    logging:
      driver: json-file
      options:
        max-size: 10m
        max-file: '3'
```

</Tab>

<Tab value="Установка файлами">

Создайте папку и в ней `docker-compose.yml`:

```bash title="Терминал"
mkdir -p /opt/submw-go
cd /opt/submw-go
```

```yaml title="docker-compose.yml"
services:
  submw-go:
    image: ghcr.io/mrvibecodic/remnawave-subscription-middleware-go:dev
    container_name: submw-go
    restart: always
    network_mode: host
    environment:
      - SUBMW_GO_LISTEN=127.0.0.1:8090
      - SUBMW_GO_SECRET=секрет_из_админки
    logging:
      driver: json-file
      options:
        max-size: 10m
        max-file: '3'
```

`network_mode: host` — Go видит панель так же, как сайт на этом сервере, а слушает только `127.0.0.1`: снаружи до него не достучаться.

<Callout type="warn">
Не убирайте строку `SUBMW_GO_LISTEN=127.0.0.1:8090`. Без неё Go в режиме `network_mode: host` слушает порт 8090 на всех адресах сервера, и до него можно достучаться из интернета — защищать его будет только секрет.
</Callout>

</Tab>
</Tabs>

Вместо `секрет_из_админки` вставьте секрет из первого шага.

</Step>
<Step>

### Запустите [#go-run]

```bash title="Терминал"
docker compose up -d submw-go
```

</Step>
<Step>

### Проверьте [#go-check]

«О системе» → блок «Go-сервис» → «Проверить». Должно появиться «Go-сервис работает», а в заголовке блока «Сессии» на вкладке «Пользователи» — бейдж «Go». Прослойка находит сервис сама: в Docker по адресу `http://submw-go:8090`, при установке файлами — `http://127.0.0.1:8090`. Если вы назвали сервис иначе или сменили порт, впишите адрес в поле «Адрес Go-сервиса».

</Step>
</Steps>

## Интервал опроса [#go-interval]

Когда Go появляется первый раз, прослойка ставит опрос раз в минуту (если вы не меняли прежние две минуты). Дальше интервал — ваш: «Пользователи» → блок «Сессии» → «Как часто опрашивать ноды».

<Callout type="warn">
Каждый опрос — минимум два запроса к панели на каждую ноду. При 20 нодах раз в минуту это около 58 тысяч запросов в сутки, раз в две минуты — вдвое меньше. Сколько уходит на самом деле — видно в журнале опросов и на «О системе» → «Запросы к панели», строка «Go-сервис: опрос нод».
</Callout>

## Значок и журнал [#go-journal]

В заголовке блока «Сессии» бейдж показывает, кто опрашивает ноды:

| Бейдж | Что значит |
|---|---|
| Go | Ноды опрашивает Go |
| PHP | Ноды опрашивает прослойка — Go не стоит или выключен |
| PHP · Go не отвечает, PHP вместо Go (жёлтый) | Go был, но сейчас не справился — опрос делает прослойка. Причина — при наведении и на «О системе» в блоке «Go-сервис» |

Ниже — «Журнал опросов»: каждый опрос за 7 дней — кто опрашивал, сколько нод ответило, сколько длился опрос, сколько ушло запросов к панели и что не так. Сверху — сводка за сутки или 3 дня отдельно по Go и по прослойке. Опросы до установки Go тоже в журнале — с ними и сравнивать. «CSV за 7 дней» выгружает журнал целиком для разбора.

Если нода не ответила из-за сбоя сети или ошибки панели, Go в том же опросе один раз пробует её снова — когда на это хватает времени. Такие опросы отмечены «повтор», при наведении видно, какие ноды повторялись; найти их можно фильтром «С повтором». Ноду, которой нет в панели или на которую у токена нет прав, Go не повторяет.

## Список пользователей [#go-users]

Прослойке список пользователей панели нужен в нескольких местах: вкладка «Пользователи», лог запросов, аренда WireGuard, лимиты устройств для «Сессий», канал приложений, оверрайды. Панель отдаёт его страницами по 250 — прослойка запрашивает их по очереди, и при нескольких тысячах пользователей это заметно.

Go запрашивает первую страницу, узнаёт, сколько всего пользователей, и остальные страницы берёт параллельно — не больше четырёх одновременно, чтобы не нагружать панель. Каждому месту он отдаёт только нужные ему поля, полный объект пользователя — только вкладке «Пользователи». Список такой же свежий, как без Go: он собирается заново в тот же момент, что и раньше.

* **Всё или ничего.** Если хоть одна страница не загрузилась, Go не отдаёт список вовсе, и его целиком собирает прослойка. Неполного списка не бывает.
* **Сверка раз в сутки.** Планировщик сравнивает список от Go и от прослойки — число пользователей и сами адреса подписок. Если пользователя создали между двумя обходами, Go спрашивается ещё раз. Не совпало — Go перестаёт собирать список, его собирает прослойка, а в блоке «Go-сервис» появляется жёлтая строка с причиной. Сверка повторится через сутки; кнопка «Проверить» запускает её сразу.
* **«Не использовать Go»** выключает и опрос нод, и список пользователей.

На «О системе» в блоке «Go-сервис» у каждой задачи своя строка: кто её сейчас делает, когда последний раз и сколько это заняло. В «Запросах к панели» запросы Go за списком — отдельной строкой «Go-сервис: список пользователей».

## Если что-то не так [#go-trouble]

| Сообщение | Что сделать |
|---|---|
| Не отвечает: адрес не найден / соединение отклонено | Контейнер не запущен или в другой сети. Проверьте `docker compose ps` и что у `submw-go` те же `networks`, что у прослойки. |
| Секрет не подходит | В `SUBMW_GO_SECRET` не тот секрет — скопируйте текущий из админки и выполните `docker compose up -d submw-go`. |
| В Go-контейнере не задан секрет | Добавьте `SUBMW_GO_SECRET` в `environment`. |
| Версия Go-сервиса не подходит к прослойке | Обновите образ: `docker compose pull submw-go && docker compose up -d submw-go`. |
| Go не достучался до панели | Go в другой сети, чем панель. В Docker подключите его к тем же сетям, что и прослойку; при установке файлами — `network_mode: host`. |

Пока Go не справляется, ноды опрашивает и список собирает прослойка — ничего не прерывается.

## Сменить секрет, выключить, удалить [#go-off]

* **Сменить секрет** — «О системе» → «Go-сервис», кнопка рядом с секретом. До того как вы впишете новый в контейнер, всё делает прослойка.
* **Выключить** — «Не использовать Go» там же: прослойка всё делает сама, даже когда Go отвечает. Удобно для сравнения.
* **Удалить** — уберите сервис из `docker-compose.yml` и выполните `docker compose up -d --remove-orphans`; при установке файлами — `docker compose down` в папке `/opt/submw-go`. Если адрес Go не задан вручную, через неделю молчания прослойка перестанет его ждать и уберёт жёлтый бейдж.

Обновляется Go-сервис вместе с прослойкой: `docker compose pull && docker compose up -d`.
