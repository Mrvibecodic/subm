---
title: Мастер установки
description: Пять шагов в браузере, с проверкой на каждом.
---

Мастер проверяет всё, что нужно для работы: базу данных, связь с панелью, права токена, страницу подписки, а для зеркала — домен подписки панели. В конце он запрашивает подписку первого пользователя через ваш домен, как это сделал бы VPN-клиент.

<Callout>
Красные ошибки не дают перейти дальше: без этого прослойка не сможет отдавать подписку. Это база данных, связь с панелью, токен и четыре обязательных права, панель версии 2.7.4 или новее и пароль от 8 символов. Жёлтые предупреждения не мешают: можно продолжить и вернуться к ним позже на вкладке «Подключение».
</Callout>

## 1. Начало [#wz-start]

Мастер показывает домен, базу данных, версию PHP и образ. Если чего-то не хватает, здесь появится красное или жёлтое сообщение: например, нет расширения PHP, нет записи в папку `data/` или сайт открыт без HTTPS.

<Shot name="panel-1-start" alt="Начало: прослойка рядом с панелью" />

Рядом с панелью выбирать нечего: прослойка встаёт вместо текущей подписки. На отдельном сервере выберите [режим работы](/ru/docs#intro-modes):

* **Домен подписки** — вместо текущей подписки, на домене из `SUB_PUBLIC_DOMAIN` панели. Ссылки у пользователей не меняются.
* **Свой домен (зеркало)** — зеркало подписки на новом домене. Пользователи получают ссылки на домене зеркала.

<Shot name="standalone-1-start" alt="Начало на отдельном сервере: выбор домена" />

При установке файлами здесь же выберите «Без Docker».

## 2. Панель [#wz-panel]

Рядом с панелью адрес уже подставлен: `http://remnawave:3000`. Вставьте API-токен и нажмите «Проверить» — мастер покажет версию панели и права токена.

<Shot name="panel-2-panel" alt="Панель на связи, права токена в порядке" />

На отдельном сервере укажите адрес, по которому вы входите в панель. Если панель ставилась установщиком с защитной cookie (eGames, remnawave-reverse-proxy), вставьте ссылку входа целиком, например `https://panel.example.com/auth/login?abcd=1234`. Мастер возьмёт из неё адрес и cookie.

<Shot name="standalone-2-panel" alt="Cookie взята из ссылки входа" />

В блоке «Панель закрыта защитой» есть ещё поле **X-Api-Key** для панели за авторизацией Caddy (caddy-with-auth, Tiny Auth) и галочка **«Проверять сертификат панели»** — её снимают, если у панели самоподписанный сертификат.

Если домен подписки в панели отличается от домена, на котором открыт мастер, будет предупреждение: ссылки пользователей ведут на домен из панели.

### Если проверка не прошла [#wz-panel-errors]

| Сообщение | Что сделать |
| --- | --- |
| Панель закрыта защитной cookie | Вставьте в поле адреса ссылку входа в панель целиком |
| Cookie не подошла | Скопируйте ссылку входа заново: часть после «?» и есть cookie |
| Панель найдена, но токен не принят | Скопируйте токен целиком ещё раз. Если он удалён в панели — создайте новый |
| Это не API-токен | Нужен токен из Settings → API Tokens |
| У токена нет нужных прав | Создайте токен со всеми правами |
| Панель закрыта авторизацией Caddy — нужен X-Api-Key | Ключ — на странице входа Caddy вашей панели, раздел API-keys |
| Cloudflare не пропускает запросы к панели | В Cloudflare → Security → WAF добавьте правило Skip для IP сервера прослойки или выключите Bot Fight Mode |
| Это домен подписки, а нужен домен панели | Укажите адрес, по которому входите в панель |
| Внутренний адрес, с другого сервера он не виден | На отдельном сервере нужен публичный адрес панели |
| Контейнер панели не найден | Прослойка не в одной docker-сети с панелью. Проверьте имя сети в `docker-compose.yml` |
| У панели самоподписанный сертификат | Снимите галочку «Проверять сертификат панели» |
| Панель устарела | Обновите панель до 2.7.4 или новее |

## 3. Страница подписки [#wz-subpage]

Когда ссылку подписки открывают в браузере, прослойка показывает страницу подписки Remnawave из контейнера `subscription-page`. Рядом с панелью это контейнер панели, на отдельном сервере — сервис `subpage` из вашего `docker-compose.yml`. Адрес уже подставлен, мастер сразу его проверяет.

<Shot name="panel-3-subpage" alt="Страница подписки работает: прослойка рядом с панелью" />

<Callout>
На скриншоте прослойка стоит рядом с панелью: страница подписки в той же docker-сети, адрес `http://remnawave-subscription-page:3010`.

На отдельном сервере в режиме «вместо текущей подписки» адрес будет `http://subpage:3010` — это сервис `subpage` из вашего `docker-compose.yml`, мастер подставит его сам. Этот сервис обязателен: без него ссылка подписки в браузере не откроется как страница. У зеркала этого шага нет, вместо него — [«Домен подписки»](#wz-origin).
</Callout>

Если страница не отвечает, можно продолжить и вернуться к этому позже. На отдельном сервере это чаще всего значит, что у сервиса `subpage` не заполнены адрес панели или токен: посмотрите `docker compose logs subpage`. Галочку «Показывать страницу подписки» не снимайте: без неё ссылка в браузере откроется служебным ответом панели вместо страницы.

### Для зеркала: домен подписки [#wz-origin]

У зеркала вместо этого шага — «Домен подписки». Вставьте ссылку подписки любого пользователя из панели. Мастер сам найдёт домен и префикс и проверит, что подписка по ней открывается.

<Shot name="mirror-3-origin" alt="Домен подписки для зеркала" />

С галочкой «Показывать в браузере страницу подписки с этого домена» в браузере откроется страница подписки с домена панели.

## 4. Вебхук [#wz-webhook]

Через вебхук панель сразу сообщает прослойке, что пользователь истёк, заблокирован или продлён. Мастер сам создал секрет и собрал три строки для `.env` панели:

<Shot name="panel-4-webhook" alt="Строки для .env панели" />

Скопируйте их в `.env` панели и перезапустите её:

```bash title="Терминал, сервер панели"
cd /opt/remnawave && docker compose down && docker compose up -d
```

Это можно сделать и после установки: те же строки есть на вкладке «Вебхуки». Если нужен свой секрет, впишите его в блоке «Свой секрет»: ровно 64 латинские буквы и цифры. На панели 3.2.0 и новее мастер покажет, включены ли в ней вебхуки.

## 5. Пароль [#wz-admin]

Логин и пароль для входа в админку. Пароль — не короче 8 символов.

<Shot name="panel-5-admin" alt="Пароль и дополнительная защита" />

**«Дополнительная защита»** оставляет вход в админку только по секретной ссылке: без неё `/admin/` показывает страницу-заглушку. Мобильное приложение работает и с защитой. Включить или выключить её можно потом на вкладке «Подключение».

Нажмите «Установить».

## Готово [#wz-done]

Мастер создаёт базу, записывает настройки и запрашивает подписку первого пользователя через ваш домен.

<Shot name="panel-6-done" alt="Установка завершена" />

* **«Подписка пользователя … открывается через ваш домен»** — всё работает.
* **«В панели ещё нет пользователей»** — создайте пользователя и откройте его ссылку в VPN-клиенте.
* **Жёлтое сообщение** — прослойка установлена, но подписка через домен не открылась. Под сообщением есть подсказка, а проверку можно повторить на вкладке «Подключение».

С «Дополнительной защитой» здесь же будет ссылка для входа. Сохраните её и откройте один раз в каждом браузере и на телефоне, откуда нужен доступ. Кнопка «Войти в админку» ведёт на форму входа.

<Shot name="login" alt="Вход в админку" />
