<Callout>
Рекомендуем ставить [вручную через Docker Compose](/ru/docs/install/compose): так понятнее, что и куда ставится, и проще разобраться, если что-то не заработает. Скрипт делает то же самое, только сам.
</Callout>

## Запуск [#script-run]

Подключитесь к серверу по SSH и выполните:

```bash title="Терминал"
curl -fsSL https://raw.githubusercontent.com/Mrvibecodic/remnawave-subscription-middleware/main/install.sh -o install.sh
sudo bash install.sh
```

Скрипт предложит четыре варианта установки:

1. **Docker рядом с панелью** — тот же сервер, docker-сеть панели.
2. **Docker на отдельном сервере, где уже есть реверс-прокси** — nginx, Caddy или панель хостинга.
3. **Docker на чистом сервере с Caddy** — Caddy выпустит сертификат сам.
4. **Без Docker** — nginx, PHP-FPM и certbot прямо на сервер. Только для зеркала.

Готовый compose с nginx в контейнере скрипт пока не ставит — только [вручную](/ru/docs/install/compose).

## Что спросит скрипт [#script-questions]

В квадратных скобках — ответ по умолчанию: чтобы его принять, нажмите Enter.

<Tabs items={['1. Рядом с панелью', '2–3. Отдельный сервер', '4. Без Docker']}>
<Tab value="1. Рядом с панелью">

| Вопрос | По умолчанию | Что ответить |
| --- | --- | --- |
| Тег образа | `v1` | `v1` — стабильный релиз, `dev` — тестовая версия |
| Имя docker-сети панели | `remnawave-network` | оставьте, если панель ставилась стандартно |
| Внутренний URL панели | `http://remnawave:3000` | имя контейнера панели и порт |
| Внутренний URL контейнера subscription-page | `http://remnawave-subscription-page:3010` | имя контейнера страницы подписки и порт |
| Локальный порт прослойки | `8080` | на этот порт реверс панели будет отправлять домен подписки |

Обычно на все вопросы достаточно нажать Enter. API-токен скрипт здесь не спрашивает: его вводят в мастере установки.

</Tab>
<Tab value="2–3. Отдельный сервер">

| Вопрос | По умолчанию | Что ответить |
| --- | --- | --- |
| Тег образа | `v1` | `v1` — стабильный релиз, `dev` — тестовая версия |
| Поднять MariaDB в этом же compose? | `N` | Enter — база SQLite, `y` — MariaDB |
| Домен подписки | — | домен прослойки, он зависит от режима. Вместо текущей подписки — домен подписки панели, например `sub.example.com`. Для зеркала — новый домен, например `mirror.example.com`: домен подписки панели для зеркала указывать нельзя |
| Адрес панели или ссылка входа | — | адрес панели. Если панель ставилась установщиком с защитной cookie, вставьте ссылку входа целиком: cookie скрипт возьмёт из неё сам |
| API-токен панели | — | вводимые символы не показываются. Можно оставить пустым, тогда токен спросит мастер |
| Локальный порт (только пункт 2) | `8080` | на этот порт ваш реверс-прокси будет отправлять домен |

Адрес панели, токен и cookie скрипт впишет в `docker-compose.yml` для страницы подписки и передаст мастеру, чтобы не вводить их второй раз. Режим — вместо подписки или зеркало — выбирается потом в мастере.

</Tab>
<Tab value="4. Без Docker">

Этот пункт ставит nginx, PHP-FPM и certbot прямо на сервер и работает как зеркало. Нужен чистый сервер на Ubuntu 22.04+ или Debian 12+. Скрипту нужны все файлы прослойки рядом, поэтому сначала скачайте репозиторий:

```bash title="Терминал"
sudo apt update && sudo apt install -y git
sudo git clone https://github.com/Mrvibecodic/remnawave-subscription-middleware /opt/remnawave-subscription-middleware
cd /opt/remnawave-subscription-middleware
sudo bash install.sh        # пункт 4
```

Скрипт спросит домен зеркала, домен подписки панели, базу (SQLite или MariaDB), способ выпуска сертификата (по 80 порту или через Cloudflare DNS) и e-mail для Let's Encrypt.

<Callout type="warn">
Если на сервере уже есть nginx, скрипт удалит его вместе с папкой `/etc/nginx`. Перед этим он сохранит копию в `/root` и дважды спросит подтверждение, но другие сайты на этом nginx перестанут работать. Для сервера с другими сайтами выберите [установку файлами](/ru/docs/install/files).
</Callout>

</Tab>
</Tabs>

## Что делает скрипт [#script-does]

<Steps>
<Step>Ставит Docker, если его ещё нет.</Step>
<Step>Если в `/opt/remnawave-subscription-middleware` уже лежит `docker-compose.yml`, сохраняет его рядом с пометкой `.bak` и останавливает старые контейнеры. Данные прослойки остаются.</Step>
<Step>Скачивает нужный файл как `docker-compose.yml` (для пункта 3 ещё `Caddyfile`) из той же ветки, что и выбранный образ, и вписывает в него ваши ответы.</Step>
<Step>Скачивает образы и запускает контейнеры.</Step>
<Step>Печатает, что сделать дальше, и ссылку мастера установки.</Step>
</Steps>

## Результат [#script-result]

Так выглядит конец вывода для пункта 1:

```text title="Вывод"
================ ГОТОВО (Docker) ================
Compose: /opt/remnawave-subscription-middleware/docker-compose.yml
1) Направьте домен подписки на прослойку в реверсе ПАНЕЛИ (подписки недоступны, пока не пройдёте мастер):
     Caddy (remnawave-reverse-proxy): SUB_BACKEND_URL=127.0.0.1:8080 у контейнера Caddy в /opt/remnawave/docker-compose.yml, затем docker compose up -d remnawave-caddy
     nginx (eGames): в /opt/remnawave/nginx.conf  upstream json { server 127.0.0.1:8080; }  затем docker exec remnawave-nginx nginx -s reload
2) Откройте мастер установки:
     https://<домен-подписки>/admin/?kijm36wa=d4542e707f0836cc5340e737

Обновление: cd /opt/remnawave-subscription-middleware && docker compose pull && docker compose up -d
```

В пункте 1 скрипт не спрашивает домен, поэтому в ссылке стоит `<домен-подписки>`. Замените его своим доменом, остальное оставьте как есть. В пунктах 2 и 3 домен в ссылке уже ваш.

Дальше: [направьте домен на прослойку](/ru/docs/install/compose#compose-domain) (кроме пункта 3) и откройте [мастер установки](/ru/docs/wizard).

<Callout>
Если прослойка на этом сервере уже была установлена, скрипт так и напишет: данные сохранены, мастер проходить не нужно.
</Callout>
