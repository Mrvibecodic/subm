Чат поддержки связан с Telegram в обе стороны, и эти стороны не зависят друг от друга:

* **Сайт → Telegram.** Прослойка сама отправляет боту сообщение посетителя. Если сообщения в Telegram приходят — эта сторона работает.
* **Telegram → сайт.** Когда оператор отвечает, Telegram сам отправляет ответ на адрес прослойки — это вебхук бота, `https://домен-прослойки/chat.php?tg=1`. Если вебхук не установлен или Telegram не может до него достучаться, ответы до сайта не доходят.

Поэтому «в Telegram приходит, а обратно нет» почти всегда значит одно из трёх: вебхук не установлен, Telegram не может достучаться до сервера прослойки или прослойка не поняла, к какому диалогу ответ.

## Найдите причину [#chat-find]

«Чат поддержки» → блок «Переотправка в Telegram» → «Статус вебхука». Прослойка спросит у Telegram, куда он отправляет ответы и что пошло не так. Ошибку Telegram пишет целиком, например `Wrong response from the webhook: 401 Unauthorized`, — в таблице только её конец.

| Статус | Что значит и что сделать |
|---|---|
| «вебхук не установлен» | Бот подключён, но Telegram не знает, куда отправлять ответы. Нажмите «Установить вебхук бота». Вебхук ставится и сам, когда вы сохраняете настройки чата с включённой переотправкой, — если тогда что-то пошло не так, ошибка была в сообщении после сохранения. |
| «адрес не тот, что задан в прослойке» | Вебхук бота указывает в другое место. Обычно этот же бот подключён ещё к одной программе — другому боту, скрипту, конструктору — и она поставила свой адрес. Нажмите «Установить вебхук бота». Если адрес снова меняется, создайте для чата поддержки отдельного бота в @BotFather: один бот не может отправлять ответы в два места. |
| `Connection timed out`, `Connection refused`, `Failed to resolve host`, `SSL error` | Telegram не может достучаться до сервера прослойки: адреса Telegram закрыты у провайдера или в фаерволе, у домена нет нормального сертификата, сайт не на порту 443. [Вынесите вебхук на другой сервер](#chat-move). |
| `401 Unauthorized` | Telegram достучался, но прислал не тот секрет: вебхук ставила другая установка прослойки с этим же ботом или его меняли вручную. Нажмите «Установить вебхук бота». |
| `403 Forbidden` | Запрос режет защита перед сайтом (Cloudflare, WAF) — разрешите в ней запросы к `/chat.php`. Или выключена «Переотправка в Telegram» — включите и сохраните. |
| `404`, `502`, `503` | Адрес из строки «Вебхук бота» ведёт не на прослойку, или прослойка за реверс-прокси не отвечает. Проверьте, что в строке «Вебхук бота» домен прослойки и что реверс-прокси отдаёт ей `/chat.php`. |
| «ошибок нет», «в очереди: 0» | Если ответов всё равно нет — Telegram их доставляет, но прослойка не поняла, к какому диалогу они. См. [«Ответ дошёл, но не попал в диалог»](#chat-route). |

«В очереди» — сколько ответов Telegram не смог доставить и держит у себя. Если число растёт — смотрите на ошибку рядом.

<Callout>
Рядом с ошибкой показано, как давно она была. Telegram хранит последнюю ошибку и после того, как всё починилось. Если ей несколько часов, а «в очереди» 0 — она уже не актуальна.
</Callout>

<Callout type="warn">
Когда вебхук устанавливается заново, ответы, которые Telegram не смог доставить, сбрасываются. Оператору нужно ответить на них ещё раз — в Telegram или во вкладке «Чат поддержки».
</Callout>

### Ответ дошёл, но не попал в диалог [#chat-route]

* Отвечайте именно **ответом** (Reply, «Ответить») на сообщение бота — в нём есть метка `#s` с номером диалога. Обычное сообщение в чат прослойка ни к какому диалогу не привяжет. Второй способ — команда `/r 123 текст`, где 123 — номер диалога.
* Пишите в тот чат, номер которого указан в поле «Chat ID оператора / группы». Сообщения из других чатов прослойка пропускает — например, из личного чата с ботом, когда указана группа.
* Принятый ответ появляется в диалоге во вкладке «Чат поддержки», а бот удаляет его из Telegram (в группе — если у бота есть право удалять сообщения).

Почему ответ не принят, прослойка пишет в лог: в Docker — `docker compose logs submw`, при установке файлами — лог ошибок PHP-FPM. Строки начинаются с `submw chat tg:`.

## Вынести вебхук на другой сервер [#chat-move]

Если Telegram не может достучаться до сервера прослойки, поставьте между ними другой сервер, до которого Telegram достаёт, — обычно зарубежный, подойдёт и сервер панели или ноды. Веб-сервер на нём принимает запрос Telegram и передаёт его прослойке как есть, вместе с секретом. Сам он ничего не хранит, токен бота на него не попадает.

<Callout type="warn">
Этот сервер сам должен открывать сайт прослойки. Проверьте с него: `curl -sI https://sub.example.com` (подставьте домен прослойки) — должен прийти ответ, а не тайм-аут.
</Callout>

<Steps>
<Step>

### Заведите поддомен [#chat-move-domain]

Например, `tg-hook.example.com` — с A-записью на IP этого сервера. Telegram отправляет вебхук только по https и только на порты 443, 80, 88 или 8443; ниже везде 443.

</Step>
<Step>

### Настройте веб-сервер [#chat-move-server]

Оба варианта пропускают к прослойке только `/chat.php?tg=1`, на всё остальное отвечают 404. Вместо `sub.example.com` впишите домен прослойки — тот, что сейчас в строке «Вебхук бота».

<Tabs groupId="web" persist items={['nginx', 'Caddy']}>
<Tab value="nginx">

```nginx title="/etc/nginx/conf.d/tg-hook.conf"
server {
    listen 443 ssl;
    server_name tg-hook.example.com;

    ssl_certificate     /etc/letsencrypt/live/tg-hook.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/tg-hook.example.com/privkey.pem;

    location = /chat.php {
        if ($arg_tg != "1") { return 404; }
        proxy_pass https://sub.example.com;
        proxy_ssl_server_name on;
        proxy_set_header Host sub.example.com;
        proxy_connect_timeout 10s;
        proxy_read_timeout 30s;
    }

    location / {
        return 404;
    }
}
```

Сертификат выпустите как для любого сайта, например `certbot certonly --nginx -d tg-hook.example.com`. Затем:

```bash title="Терминал"
nginx -t && systemctl reload nginx
```

</Tab>
<Tab value="Caddy">

```text title="Caddyfile"
tg-hook.example.com {
    @tg {
        path /chat.php
        query tg=1
    }
    handle @tg {
        reverse_proxy https://sub.example.com {
            header_up Host sub.example.com
        }
    }
    handle {
        respond 404
    }
}
```

Сертификат Caddy получит сам. Затем:

```bash title="Терминал"
systemctl reload caddy
```

</Tab>
</Tabs>

</Step>
<Step>

### Проверьте связку [#chat-move-check]

С любого компьютера:

```bash title="Терминал"
curl -s -o /dev/null -w '%{http_code}\n' -X POST 'https://tg-hook.example.com/chat.php?tg=1'
```

| Код | Что значит |
|---|---|
| 401 | Всё правильно: запрос дошёл до прослойки, и она отказала, потому что у проверки нет секрета Telegram. В логе прослойки при этом появится строка `bad secret token` — это от проверки |
| 403 | Запрос дошёл, но его режет защита перед сайтом прослойки — или переотправка в Telegram выключена |
| 404 | Веб-сервер не подхватил настройки или в адресе опечатка |
| 502, 504 или нет ответа | Этот сервер не достаёт до сайта прослойки — проверьте домен в `proxy_pass` или `reverse_proxy` |

</Step>
<Step>

### Впишите адрес в прослойку [#chat-move-admin]

<Callout type="warn">
Поле «Адрес для вебхука бота» входит в стабильную версию начиная с релиза v1.11.0. Пока он не вышел, поле есть только в тестовой версии (`dev`).
</Callout>

«Чат поддержки» → блок «Переотправка в Telegram» → «Адрес для вебхука бота»: `https://tg-hook.example.com` → «Сохранить настройки чата».

Прослойка сама переставит вебхук на новый адрес. Строка «Вебхук бота» под кнопками покажет `https://tg-hook.example.com/chat.php?tg=1`.

</Step>
<Step>

### Проверьте [#chat-move-done]

Нажмите «Статус вебхука»: адрес — новый, «ошибок нет» (или старая ошибка с давним временем — она от прежнего адреса). Напишите в чат с сайта и ответьте из Telegram — ответ должен появиться у посетителя.

</Step>
</Steps>

Чтобы вернуть как было, очистите поле «Адрес для вебхука бота» и сохраните — вебхук снова встанет на домен прослойки.

## Если и в Telegram сообщения не приходят [#chat-api]

Обратная ситуация: «Проверить доступ TG» пишет ошибку соединения — сервер прослойки сам не может достучаться до Telegram. Тогда на том же зарубежном сервере настройте прокси к API Telegram и впишите его адрес в «Базовый URL Telegram API» (например, `https://tg-api.example.com`). Вебхук при этом можно оставить как есть или вынести, как описано выше, — это независимые настройки.

<Callout type="warn">
Через этот прокси ходит токен бота. Пускайте к нему только IP сервера прослойки — иначе ботом сможет управлять кто угодно, кто узнает адрес.
</Callout>

<Tabs groupId="web" persist items={['nginx', 'Caddy']}>
<Tab value="nginx">

```nginx title="/etc/nginx/conf.d/tg-api.conf"
server {
    listen 443 ssl;
    server_name tg-api.example.com;

    ssl_certificate     /etc/letsencrypt/live/tg-api.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/tg-api.example.com/privkey.pem;

    allow 203.0.113.10;
    deny  all;

    location /bot {
        proxy_pass https://api.telegram.org;
        proxy_ssl_server_name on;
        proxy_set_header Host api.telegram.org;
        proxy_read_timeout 30s;
    }
}
```

</Tab>
<Tab value="Caddy">

```text title="Caddyfile"
tg-api.example.com {
    @submw {
        remote_ip 203.0.113.10
        path /bot*
    }
    handle @submw {
        reverse_proxy https://api.telegram.org {
            header_up Host api.telegram.org
        }
    }
    handle {
        respond 403
    }
}
```

</Tab>
</Tabs>

`203.0.113.10` замените на IP сервера прослойки. Затем в админке: впишите адрес, сохраните и нажмите «Проверить доступ TG» — должно появиться «бот доступен».
