Всё делается на вкладке «Бэкап» в разделе «Обслуживание».

## Что попадает в бэкап [#backup-what]

Все настройки и данные прослойки: подключение к панели, оверрайды, грейс, доп. конфиги, ключи защищённого канала и приложения, журналы и статистика, а также логин и пароль админки.

Подключение к базе данных в бэкап не входит. Восстановление идёт в ту базу, к которой прослойка подключена сейчас, поэтому бэкап с SQLite можно восстановить на MySQL и наоборот. Логотип, геобазы и приложение для Android прослойка потом скачает сама.

## Создать [#backup-create]

<Shot name="backup-create" alt="Бэкап → Создать бэкап" />

* **Сохранить на сервере** — файл появится в списке «Бэкапы на сервере».
* **Скачать** — файл сразу скачается и на сервере не останется.
* **Пароль** — по желанию. Без пароля файл может прочитать любой, у кого он окажется, а в нём токен панели и другие секреты. Пароль прослойка не хранит: если его забыть, файл не восстановить.
* **Без журналов и статистики** — файл будет намного меньше.

## Восстановить [#backup-restore]

<Steps>
<Step>

### Выберите файл [#backup-pick]

В списке «Бэкапы на сервере» нажмите «Восстановить» у нужного бэкапа. Файл с компьютера сначала загрузите кнопкой «Загрузить файл».

</Step>
<Step>

### Проверьте, что внутри [#backup-check]

Окно покажет дату бэкапа, версию прослойки, базу, число записей и логин. Если нужно, отметьте «Оставить текущий вход в админку» или «Без журналов и статистики».

</Step>
<Step>

### Подтвердите [#backup-confirm]

Введите слово «восстановить». Перед заменой прослойка сама сохранит снимок текущих данных: он появится в списке как «снимок до восстановления», и из него можно вернуть всё обратно.

</Step>
</Steps>

<Shot name="backup-restore" alt="Бэкап → Восстановление" />

<Callout type="warn">
Пока идёт восстановление, подписки могут отвечать с задержкой — на большой базе лучше делать это в спокойное время. Если восстановление сорвётся, текущие данные не изменятся.
</Callout>

Вместе с данными станут как в бэкапе:

* **Логин, пароль и вход по секретной ссылке** — если не отметить «Оставить текущий вход в админку». Если логин сменится, админка попросит войти заново.
* **Телефоны приложения для Android.** Телефоны, привязанные после бэкапа, придётся привязать заново, а отвязанные после него снова получат доступ.
* **Ключ защищённого канала.** Clod Clash сам переключится на него при следующем обновлении подписки.

Служебные настройки этой установки остаются текущими: планировщик, проверка обновлений и настройки бэкапа.

## Перенос на другой сервер [#backup-move]

1. На старом сервере создайте бэкап и скачайте его.
2. На новом [установите прослойку](/ru/docs/install) и пройдите мастер.
3. На вкладке «Бэкап» загрузите файл и восстановите его.
4. Проверьте вебхук и домен подписки в панели — [После установки](/ru/docs/after-install).

## Большие файлы [#backup-big]

Под списком бэкапов написано, какой размер файла принимает сервер. В Docker по умолчанию это 2 МБ, а полный бэкап с журналами обычно больше. Можно положить файл прямо в папку с бэкапами или поднять лимит.

### Положить файл в папку [#backup-copy]

<Tabs groupId="backup-big" items={['Docker', 'Файлами на хостинге']}>
<Tab value="Docker">

Из папки с `docker-compose.yml`:

```bash title="Терминал"
docker compose cp submw-backup.json.gz submw:/var/www/html/data/backups/
```

</Tab>
<Tab value="Файлами на хостинге">

Загрузите файл по SFTP в папку `data/backups` внутри папки сайта. Файл должен быть доступен на чтение пользователю, от которого работает PHP, — его имя показано под списком бэкапов.

</Tab>
</Tabs>

Файл появится в списке, дальше — как обычно.

### Поднять лимит [#backup-limit]

Лимит есть у PHP и у веб-сервера, поднимать нужно оба. Память PHP (`memory_limit`) трогать не нужно: загружаемый файл пишется на диск, а не в память.

<Tabs groupId="backup-big" items={['Docker', 'Файлами на хостинге']}>
<Tab value="Docker">

Рядом с `docker-compose.yml` создайте файл с лимитами PHP:

```ini title="uploads.ini"
upload_max_filesize = 64M
post_max_size = 64M
```

В `docker-compose.yml` у сервиса `submw` добавьте строку в `volumes` и перезапустите контейнер:

```yaml title="docker-compose.yml"
    volumes:
      - submw-data:/var/www/html/data
      - ./uploads.ini:/usr/local/etc/php/conf.d/uploads.ini:ro
```

```bash title="Терминал"
docker compose up -d
```

Внутри образа у nginx свой лимит — 8 МБ, поэтому так загружаются файлы до 8 МБ. Файл больше положите в папку, как описано выше.

</Tab>
<Tab value="Файлами на хостинге">

**1. Лимит PHP.** Проще всего — в панели хостинга, в настройках PHP сайта: поставьте `upload_max_filesize` и `post_max_size`, например `64M`. Если таких настроек нет, создайте в корне сайта файл `.user.ini` — PHP-FPM подхватит его в течение 5 минут:

```ini title=".user.ini"
upload_max_filesize = 64M
post_max_size = 64M
```

**2. Лимит веб-сервера.**

* **nginx** — в блоке `server` сайта `client_max_body_size 64m;`, затем `nginx -s reload`.
* **Caddy** размер не ограничивает, ничего делать не нужно.

</Tab>
</Tabs>

Если перед прослойкой стоит свой nginx, например у панели, поднимите и там `client_max_body_size` — по умолчанию у nginx 1 МБ. Caddy размер не ограничивает.

Под списком бэкапов показан лимит PHP — после правки он поменяется.

## По расписанию [#backup-auto]

Включите «Сохранять по расписанию» — прослойка будет сама сохранять бэкап на сервере.

* **Каждые, часов** — от 1 до 24, по умолчанию 24. При включении и при смене интервала бэкап делается сразу, дальше часы отсчитываются от него. Бэкапы, сохранённые вручную, отсчёт не сбрасывают.
* **Сколько хранить** — от 1 до 200, по умолчанию 7. Более старые бэкапы по расписанию удаляются сами.
* **Пароль** для таких бэкапов — по желанию. Без него не включится отправка в Telegram.

Нужен работающий планировщик. В Docker он уже запущен, при установке файлами его нужно [добавить в cron](/ru/docs/install/files#files-cron).

Снимков до восстановления хранится 3 последних. Сохранённые вручную и загруженные файлы не удаляются.

## Отправка в Telegram [#backup-telegram]

Бэкапы по расписанию могут приходить в чат с вашим ботом, копия при этом остаётся на сервере.

<Steps>
<Step>

### Создайте бота [#backup-tg-bot]

Отдельного — у [@BotFather](https://t.me/BotFather). Бот чата поддержки не подойдёт: у него включён вебхук.

</Step>
<Step>

### Напишите боту [#backup-tg-write]

Любое сообщение из своего аккаунта. Чтобы бэкапы приходили в группу или канал, добавьте бота туда.

</Step>
<Step>

### Проверьте связь [#backup-tg-check]

Вставьте токен бота и нажмите «Проверить связь». Прослойка найдёт чат, пришлёт в него тестовое сообщение и закрепит чат за вашим аккаунтом. Затем включите «Отправлять в Telegram».

</Step>
</Steps>

* Отправка включается только с паролем на бэкапы по расписанию: в бэкапе токен панели и другие секреты.
* Чат закреплён за аккаунтом, который его выбрал. Если боту напишет кто-то ещё, бэкапы к нему не уйдут. Перенести бэкапы в другой чат может только этот аккаунт: написать боту оттуда или добавить его в группу и снова нажать «Проверить связь». «Сбросить привязку» стирает чат и закрепление — отправка встанет, пока связь не проверят заново.
* Файл больше 50 МБ приходит частями `.001`, `.002`… Скачайте все части и объедините их в 7-Zip (Файл → Объединить файлы) — получится файл для восстановления.
* Если отправить не получилось, прослойка повторит попытку без нового бэкапа. Если бэкап не создался, в чат придёт одно сообщение об ошибке.
* Запросы к Telegram идут по адресу Bot API из настроек чата поддержки, если он там задан.
